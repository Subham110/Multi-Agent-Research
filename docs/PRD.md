# Product Requirements Document

## Product name

ResearchMesh AI

## Product summary

ResearchMesh is an AI-first research workspace where specialized agents collaborate to create evidence-grounded reports. Users define a research question and objective, observe the workflow, inspect sources, and receive a quality-gated report.

## Problem

Single-model research responses can miss evidence, merge contradictory claims, invent citations, perform calculations incorrectly, or produce polished writing without adequate verification. ResearchMesh separates collection, analysis, writing, and criticism into explicit roles with bounded self-correction.

## Target users

- Product and strategy teams
- AI and software engineers
- Startup founders
- Analysts and consultants
- Students and academic researchers
- Market and competitive intelligence teams

## Core user stories

1. As a researcher, I can submit a topic, objective, depth, and focus URLs.
2. As a researcher, I can see which agent and tool is active.
3. As a researcher, I can reconnect without losing workflow history.
4. As a researcher, I can read a cited final report.
5. As a researcher, I can inspect every source in a controlled registry.
6. As a workspace administrator, I can prevent public registration.
7. As an administrator, I can isolate tenant data and control concurrency.
8. As an operator, I can inspect failures, retry safely, and monitor dependencies.

## Functional requirements

### Authentication

- Tenant slug, email, and password login
- Argon2 password hashing
- JWT access token
- Registration disabled by default
- Bootstrap administrator command

### Research creation

- Topic required
- Optional objective
- Quick, Standard, and Deep modes
- Optional focus URLs
- Configurable bounded reflections and revisions
- Per-user active-job limit

### Agent workflow

- Researcher, Analyst, Writer, and Critic
- Bounded self-reflection for every role
- Critic-controlled Writer revision loop
- PostgreSQL LangGraph checkpoints
- Job cancellation at node boundaries

### Tools

- Web search grounding
- URL context
- arXiv metadata and PDF reading
- Isolated Python code execution
- Vector-memory retrieval

### Report

- Markdown structure
- Executive summary
- Competing views and limitations
- Controlled source keys `[S1]`, `[S2]`, etc.
- Deterministic invalid-key rejection
- Critic score plus deterministic citation score
- Final references generated by application code

### Dashboard

- Workspace KPIs
- Research composer
- Recent job list
- Progress and current agent
- Live event timeline
- Final report view
- Source view

## Non-functional requirements

### Performance

- Research POST responds after queueing, not after completion.
- Health endpoint does not call external dependencies.
- Readiness verifies PostgreSQL and Redis.
- Live events are pushed without polling as the primary path.

### Reliability

- Queue retry for connection failures
- Late task acknowledgement
- Bounded task execution time
- Retry-safe report/source persistence
- Durable graph checkpoints
- Persisted event replay

### Security

- Strict production CORS
- Environment/mounted secrets
- Tenant filters on every object read
- One-time WebSocket tickets
- Prompt-injection boundary
- No hidden reasoning persistence
- No local arbitrary code execution
- PDF byte and page limits

### Observability

- Structured JSON logs
- Job status, progress, agent, error, and timestamps
- Persisted agent events
- Health/readiness endpoints
- Production metrics and tracing extension points

## Success metrics

- Completion rate
- Median and p95 job duration
- Source count and source diversity
- Citation validity rate
- Critic pass rate
- Revision count
- User-rated usefulness
- Benchmark factual accuracy
- Cost per completed report

## Explicit non-claim

The product must not advertise “significantly more accurate than a single model” until an evaluation on representative questions demonstrates a statistically meaningful improvement.
